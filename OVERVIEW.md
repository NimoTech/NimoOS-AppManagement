# NimoOS-AppManagement Overview

NimoOS-AppManagement is the microservice responsible for full lifecycle management of containerized apps, integrating Docker Compose and the NimoOS AppStore. Current version `v1.9.0-alpha1` (`common/constants.go`).

---

## Core Responsibilities

- Install, uninstall, start, stop, and update Docker Compose apps
- AppStore catalog sync (auto-refreshes every 10 minutes via a `main.go` cron)
- Registration and management of multiple AppStores (including a built-in default store)
- Docker image management (pull, version check)
- Docker data root migration (stop Docker + rsync when switching storage disks)
- App health checks (HTTP port reachability)
- Port conflict detection
- Compose YAML validation (supports dry-run), compatible with the legacy `x-casaos` extension field
- Publishes app lifecycle events to MessageBus
- Hides system-level compose apps/containers from the App grid (`nimoos.system=true` label)

## App Install Flow

```
POST /v2/app_management/compose
  1. Parse Compose YAML (compose-spec/compose-go)
  2. Validate port conflicts
  3. Create working directory: {AppsPath}/{appName}/ (default /var/lib/nimoos/apps/)
  4. Write docker-compose.yml
  5. Run docker compose up asynchronously
  6. Publish progress events to MessageBus
  7. Auto-clean up on failure
```

Compatibility: when loading, `NewComposeAppFromYAML` automatically normalizes the legacy `x-casaos` extension field (both top-level and per-service) to `x-nimoos` (`service/compose_app.go`), so compose files from the CasaOS ecosystem can be installed directly.

## API Overview

### V2 API (primary, OpenAPI 3.0)

**AppStore management**
```
GET  /v2/app_management/appstore          List registered AppStores
POST /v2/app_management/appstore          Register a new AppStore (async)
DELETE /v2/app_management/appstore/{id}   Unregister an AppStore
GET  /v2/app_management/apps             List all available apps
GET  /v2/app_management/apps/upgradable  List upgradable apps
```

**Compose app management**
```
GET    /v2/app_management/compose            List installed apps
POST   /v2/app_management/compose            Install an app (supports dry-run)
GET    /v2/app_management/compose/{id}       View app details
PUT    /v2/app_management/compose/{id}       Change app config
PATCH  /v2/app_management/compose/{id}       Upgrade to the latest version
DELETE /v2/app_management/compose/{id}       Uninstall an app
PUT    /v2/app_management/compose/{id}/status Start/stop/restart
GET    /v2/app_management/compose/{id}/logs   View logs
```

**Internal web endpoints**
```
GET /v2/app_management/web/appgrid       App grid data (internal use ONLY, UI home page)
```

**Global config**
```
GET    /v2/app_management/global        View global config
PUT    /v2/app_management/global/{key}  Set global config
DELETE /v2/app_management/global/{key}  Delete global config
```

### V1 API (legacy, some still in use)

```
GET /v1/container/info    Read Docker daemon config (includes docker_root_dir)
PUT /v1/container/info    Change docker_root_dir → triggers data root migration (see below)
POST /v1/container/prune  Prune Docker resources
```

## System Component Hiding and Display Names (nimoos.* labels)

Internal system components (e.g. the ML backend behind the built-in Photos app) run as compose apps/containers, but must not show up in the user's App panel:

- **`nimoos.system: "true"`**: a compose app with any service carrying this label is filtered out of `/web/appgrid` by `isSystemComposeApp()` (`route/v2/internal_web.go`); bare containers carrying this label are likewise skipped from the container list (`service/container.go`).
- **`nimoos.display_name`**: container stats (`getContainerStats()`, `service/container.go`) prefer this label for the title, so the dashboard shows a friendly name (e.g. "Photos AI") instead of the raw container name.

## Docker Data Root Migration

When `PUT /v1/container/info` is called with `docker_root_dir` (`route/v1/docker.go`):

1. Read `/etc/docker/daemon.json` to get the current root (default `/var/lib/docker`); the target is `{docker_root_dir}/docker`. Returns immediately if the path hasn't changed.
2. Stop the docker service → migrate data with `rsync -a --ignore-existing` → write back to daemon.json and `/var/lib/nimoos/docker_root` → restart docker.
3. Throughout the process, `DockerMigrationBegin/Progress/End/Error` events are published via MessageBus (`common/message.go`), and the UI shows progress based on them.

**Migration lock**: while migration is in progress, `/var/run/nimoos/migration.lock` exists; both V1/V2 routes mount middleware (`route/v1.go`, `route/v2.go`) that returns 503 for all POST/PUT/DELETE requests, preventing install/uninstall/update from silently failing while Docker is stopped.

---

## MessageBus Events

Every stage of the app lifecycle publishes Begin/Progress/End/Error events:

- `AppInstall`, `AppUninstall`, `AppUpdate`, `AppStart`, `AppStop`, `AppRestart`
- `AppStoreRegister`, `AppStoreUnregister`
- `ImagePull`
- `DockerMigrationBegin/Progress/End/Error` (data root migration)

Event properties include: `app:name`, `app:title`, `app:icon`, `app:progress`, `docker:image:name`, etc.

## Data Storage

- App working directory: `/var/lib/nimoos/apps/{appName}/` (`AppsPath`)
- AppStore catalog cache: `/var/lib/nimoos/appstore/` (`AppStorePath`); `default/` is the built-in default store (a special case in `service/appstore.go` where the url is `"default"`, unpacked by the AppStore package)
- Docker root directory record: `/var/lib/nimoos/docker_root`
- Logs: `/var/log/nimoos/app-management.log`
- Global environment variables: `/etc/nimoos/env`

## Configuration

Defaults come from `NimoOS-Common/utils/constants` (`DefaultDataPath = /var/lib/nimoos`, etc.); see the sample at `build/sysroot/etc/nimoos/app-management.conf.sample`:

```ini
[common]
RuntimePath = /var/run/nimoos

[app]
AppStorePath = /var/lib/nimoos/appstore
AppsPath = /var/lib/nimoos/apps
LogPath = /var/log/nimoos

[server]
; Multiple third-party store sources can be configured (AllowShadows); the sample currently points at the CasaOS upstream repo
appstore = https://get.nimotech.ai/nimoos/appstore/store/main.zip
appstore = https://github.com/bigbeartechworld/big-bear-casaos/archive/refs/heads/master.zip
```

## Tech Stack

- **Framework**: Echo v4
- **Docker integration**: docker/docker (official SDK), docker/compose v2
- **Compose parsing**: compose-spec/compose-go (`x-nimoos` extension, compatible with `x-casaos`)
- **Cache**: bluele/gcache (upgrade-check result cache)
- **Scheduling**: robfig/cron v3 (AppStore 10-minute refresh)
- **Code generation**: deepmap/oapi-codegen
